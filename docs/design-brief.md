# 디자인 의뢰서 — 오늘 정상

앱인토스(토스 앱 안에서 도는 미니앱) "오늘 정상"의 화면 디자인을 의뢰합니다.
코드는 이미 동작합니다. 지금 화면은 기능은 다 있는데 "투박"합니다. 이 문서는 무엇을 왜 그려야 하는지,
무엇은 건드리면 안 되는지를 디자이너가 다른 질문 없이 알 수 있게 쓴 것입니다.

---

## 1. 이 앱이 뭔지 (한 문단)

**100대 명산 정상 스탬프.** 산 정상에 도착해서 버튼을 누르면 위치를 확인하고, 맞으면 그 산의 스탬프를 줍니다.
마라톤 완주 메달과 같습니다 — 산 정보 앱이 아니라 **수집 앱**입니다. 이용자는 산을 찾으러 이 앱을 켜는 게 아니라,
정상에서 스탬프를 받으려고, 그리고 집에서 모아둔 스탬프를 보려고 켭니다.

그래서 디자인의 중심은 두 장면입니다.
1. **정상에서 스탬프를 받는 순간** — 힘들게 올라와서 받는 보상. 여기가 앱의 클라이맥스.
2. **모아둔 스탬프를 보는 화면** — 빈 칸이 다음 목표가 되는 컬렉션.

나머지 화면은 이 두 장면을 향한 통로입니다.

---

## 2. 이용자와 상황

- 토스 이용자 중 주말 등산객. 20~50대, 등산 앱을 따로 쓰기도 하지만 스탬프는 여기서 모읍니다.
- **정상에서 씁니다.** 햇빛 강함, 장갑 낀 손, 바람, 숨 참. → 큰 글자, 큰 버튼, 한 손, 한 번의 탭.
  정상 화면에서 읽어야 하는 글자는 세 줄을 넘기지 않습니다.
- 집에서는 편하게 봅니다. 컬렉션은 여유 있게 훑는 화면이라 정보 밀도를 올려도 됩니다.
- 네트워크가 약합니다. 로딩·실패 상태가 "예외"가 아니라 자주 보는 화면입니다. 예쁘게 실패해야 합니다.

---

## 3. 톤

- **손에 잡히는 보상.** 스탬프는 화면 위 아이콘이 아니라 "찍힌 도장"처럼 느껴져야 합니다. 물성, 무게감.
- **차분한 자연.** 아웃도어 브랜드의 형광색이 아니라 산악회 배지, 국립공원 도장, 오래된 등산 수첩 쪽입니다.
- **말수가 적음.** 문구는 이미 짧게 확정되어 있습니다(§6). 문구를 늘리는 디자인은 안 됩니다.
- **자랑하고 싶게.** 컬렉션 화면은 캡처해서 친구에게 보낼 만해야 합니다. 이게 유일한 성장 경로입니다.

현재 팔레트(바꿔도 됩니다, 결과만 두 값으로 주세요):
- 주 색 `#1d674d` 짙은 숲 초록 — 버튼, 활성 상태
- 강조 `#e2632c` 주황 — 모은 스탬프 테두리, 성공 연출

---

## 4. 스탬프 (가장 중요한 컴포넌트)

96개 산 각각에 스탬프 하나. 산별 일러스트는 **이번 범위가 아닙니다.** 대신 규칙으로 96개가 자동 생성됩니다:
- 원형 도장. 안에 능선 실루엣(산마다 다름), 1000m 이상 산은 봉우리에 눈(흰 캡).
- 색은 고도로 정해짐: 600m 미만 연초록 → 600m 진초록 → 1000m 짙은 초록 → 1500m 남색.
- 모은 스탬프는 인증한 계절에 따라 하늘색이 다름(봄·여름·가을·겨울).

디자이너에게 원하는 것:
- **모음 / 미모음 두 상태의 차이를 결정**해 주세요. 지금은 "주황 실선 링 vs 회색 점선 링"인데, 미모음이
  "비어 있는 자리"로, 모음이 "찍힌 도장"으로 더 강하게 읽히면 좋겠습니다. 미모음은 흐리게, 실루엣만, 음각 등 제안 환영.
- 크기 3종이 있습니다: **40px**(홈 목록), **76px**(컬렉션 그리드), **160px**(산 상세 히어로·성공 연출). 40px에서도 구분돼야 합니다.
- 도장의 테두리 안에 산 이름과 고도를 넣을지 말지 결정해 주세요. 지금은 도장 밖 텍스트로 보여줍니다.

## 5. 화면 (그려야 할 것)

프레임 폭 375px. **상단 네비게이션 바는 그리지 마세요** — 플랫폼이 자동으로 얹습니다. 화면은 그 아래부터 시작합니다.
하단 탭바(홈 · 내 스탬프)는 우리가 그립니다.

### 5-1. 로그인 인트로 (1장)
앱을 처음 열면 보는 화면. 로그인 버튼 하나뿐입니다.
- 제목 "오늘 정상", 부제 "100대 명산 정상 스탬프"
- 히어로: 스탬프 마크 하나(160px). 뭘 모으는 앱인지 한눈에.
- CTA "토스로 로그인하기" (하단 고정)
- 파생 상태: 로딩("로그인하고 있어요"), 실패("로그인이 완료되지 않았어요 / 아래 버튼을 눌러 다시 시도해 주세요.")
  — 실패는 같은 화면에 문구만 바뀝니다. 별도 장 불필요, 문구 자리만 잡아 주세요.

### 5-2. 홈 — 산 목록 (2장: 기본 / 위치 거부)
- 제목 "오늘 정상", 부제 "가까운 산부터 보여드려요" 또는 "96곳 중 7곳을 모았어요"
- 권역 칩 가로 스크롤: `전체 · 수도권 · 강원 · 충청 · 전라 · 경상 · 제주`. 활성 하나.
- 산 카드 한 줄: [스탬프 40px] 산 이름 / "836m · 3.2km" / 모았으면 "모음" 배지. 96줄이 이어집니다.
- **위치 거부 상태**(2장째): 목록은 그대로 보이되 거리 없이 고도만. 위에 안내
  "위치를 허용하면 가까운 산부터 보여드려요. 아래 버튼을 누르면 권한을 다시 물어봐요." + 버튼 "위치 허용하기".
  막다른 화면이 아니라 **목록은 계속 쓸 수 있어야** 합니다.

### 5-3. 산 상세 — 기본 (1장)
정상에서 보는 화면입니다. §2의 "장갑·햇빛" 조건이 여기 적용됩니다.
- 히어로 스탬프 160px (모았으면 모음 상태로)
- 산 이름(예: 북한산), 부제 "높이 836m · 인증 지점 백운대"
  → "인증 지점"은 중요합니다. 봉우리가 여러 개인 산에서 어디로 가야 하는지 알려줍니다.
- 집계 최대 세 줄(0이면 그 줄 숨김): "지금 3명 등산 중" / "오늘 5명이 정상을 찍었어요" / "지금까지 128명 인증"
- 버튼 두 개: 보조 "산행 시작" (입구에서 누름, 없는 산도 있음) / 메인 "정상 인증하기" (하단 고정)
- 이미 모은 산이면 "이 산의 스탬프를 모았어요" 표시가 붙습니다.

### 5-4. 인증 성공 (1장) ★
**앱의 클라이맥스.** 여기에 디자인 시간의 절반을 써도 됩니다.
- 스탬프가 "찍히는" 연출. 지금은 0.5초 스케일 애니메이션. 도장 찍히는 느낌(살짝 커졌다 눌리는), 잉크 번짐, 종이 질감 등 제안 환영.
- 문구 "스탬프를 획득했어요" / "정상에 도착한 걸 확인했어요."
- 결과 카드 배경: 지금은 초록 그라데이션.
- 파생: 저장 실패 시 같은 자리에 "스탬프를 저장하지 못했어요 / 인터넷 연결을 확인한 뒤 다시 저장해 주세요." + 버튼 "다시 저장".
  성공 연출은 이미 봤는데 저장이 안 된 상황이라 **성공 느낌을 뺏지 않으면서** 재시도를 유도해야 합니다.

### 5-5. 인증 실패 + 정상 제안 (2장: 결과 / 이름 입력)
- 결과 카드: 제목 "정상까지 850m" 본문 "정상에 도착한 뒤 다시 눌러주세요." — 실패지만 야단치는 톤 아님.
- 그 아래 보조 버튼 **"여기도 북한산 정상이에요"** — 우리 좌표가 틀렸을 수 있으니 이용자가 제보하는 통로.
  스탬프를 주는 버튼이 아니므로 메인 CTA와 확실히 구분돼야 합니다(잘못 누르면 스탬프 받는 줄 압니다).
- 누르면(2장째): 라벨 "지금 계신 봉우리 이름을 알려주세요", 입력칸(placeholder "예: 문수봉", 20자),
  각주 "이름과 지금 위치만 보내요. 다른 사람에게는 보이지 않고, 정상 좌표를 고칠지 판단하는 데만 써요. 개인정보는 적지 말아주세요.",
  버튼 "보내기". 완료 시 "알려주셔서 고마워요. 확인해서 반영할게요."
- 다른 실패 문구도 같은 결과 카드 틀을 씁니다(따로 그릴 필요 없음): "위치 정확도가 낮아요", "고도가 정상과 달라요",
  "위치 정보가 오래됐어요", "오늘 스탬프는 이미 받았어요", "위치를 확인할 수 없어요".

### 5-6. 위치 권한 필요 (1장)
산 상세에서 권한이 없을 때. 제목 "위치 권한이 필요해요", 본문 "아래 버튼을 눌러 위치를 다시 확인해 주세요." + 버튼.
두 번 거부해도 버튼을 누르면 다시 묻습니다. 여기서 막히면 앱을 못 쓰므로, 화난 화면이 아니라 **문 여는 화면**이어야 합니다.

### 5-7. 내 스탬프 — 컬렉션 (1장) ★
집에서 보고, 캡처해서 자랑하는 화면.
- 제목 "내 스탬프", 부제 "96곳 중 7곳을 모았어요", 전체 진행 막대
- 권역 섹션 6개, 각 헤더 "수도권 3 / 14" 형식
- 3열 그리드, 칸마다 스탬프 76px + 산 이름 + (모았으면 날짜 "2026.09.05", 아니면 고도 "836m")
- 모은 것과 안 모은 것의 대비가 이 화면의 전부입니다. 7/96이어도 초라하지 않고, 96/96이면 벽처럼 보여야 합니다.
- 빈 상태(0개): "정상에 도착해서 인증하면 여기 빈 자리가 하나씩 채워져요." — 그리드는 그대로 다 보입니다.

### 5-8. 탭바 (컴포넌트)
홈 · 내 스탬프. 아이콘 + 라벨. 활성 색.

## 6. 문구는 확정입니다

§5의 따옴표 안 문구는 검수를 통과한 상태로 코드에 있습니다. 디자인상 줄이 넘치면 **줄바꿈 위치**는 바꿔도 되지만 단어는 바꾸지 마세요.
꼭 바꾸고 싶으면 이유와 함께 별도로 제안해 주세요. 특히 다음은 플랫폼 규정이라 못 바꿉니다:
- 스탬프를 "포인트", "적립", "원", "현금"으로 부르지 않음
- "앱 설치", "다운로드" 유도 문구 없음
- 가짜 버튼, 막다른 화면 없음

## 8. 범위 밖 (그리지 마세요)

지도, 코스·경로, 산별 사진·일러스트, 랭킹, 광고 자리, 포인트, 온보딩 튜토리얼, 설정 화면, 프로필.
이 앱의 화면은 위 4개 + 탭바가 전부이고 더 늘리지 않습니다.

## 9. 납품 형태

우선순위 순서. 시간이 부족하면 위에서부터.
1. **5-4 인증 성공** + **5-7 컬렉션** — 이 둘이면 방향이 정해집니다
2. 스탬프 컴포넌트 모음/미모음 + 3사이즈
3. 5-3 산 상세 기본, 5-2 홈
4. 나머지(5-1, 5-5, 5-6, 탭바)

형식: 화면별 375px 프레임 + 수치. "이 여백 16, 이 글자 17 semibold, 이 색 #xxxxxx" 수준이면 픽셀 단위로 옮깁니다.
색·글자 크기·간격은 **토큰 이름으로** 주시면 가장 좋습니다(예: 주 색, 강조 색, 제목/본문/캡션 3단계).
앱빌더로 작업하시면 내보낸 코드 그대로 주셔도 됩니다.

## 10. 열린 질문 (디자이너 판단에 맡김)

- 미모음 스탬프를 얼마나 흐리게 할지. 너무 흐리면 목표가 안 보이고, 너무 진하면 모은 것과 안 구분됩니다.
- 성공 연출을 얼마나 길게 할지. 정상에서는 빨리 캡처하고 싶어 하므로 1초 안에 끝나야 한다고 봅니다.
- 컬렉션 그리드에서 권역 헤더를 접을 수 있게 할지. 96개가 한 스크롤에 다 보이는 게 자랑에는 낫다고 봅니다.
- 도장 안에 글자(산 이름·고도)를 넣을지. 실제 국립공원 스탬프는 넣습니다.
